# 河医大助手 · 权属与市场保护方案

> 2026-11-10 · 基于 v1.1.62 线上现状逐项核文件写成 · 供 YG 选方案，未改任何产品代码、未部署、未提交

## 0 一句话结论

「承认它属于我」和「别人另做一套抢市场」是两件事：

- **权属**＝这行代码是你写的、这个包是你发的、这个名字是你的 —— 法律给得足，靠证书和时间证据坐实。
- **市场**＝「课表 + 作业 + 空教室」这个构思本身属于公共领域，人人可另行实现 —— 任何证书都覆盖不到，靠首发速度、唯一官方入口、用户口碑守住。

所以打法是四件一起做：**权属坐实 + 名字注册 + 许可证约束 + 首发留痕**。

## 2 三套方案（先选，再动手）

### A 补齐型 —— 推荐，改动最小、零成本、线上零影响

做这五件：

1. **提交软著登记**。中国版权保护中心 `register.ccopyright.com.cn`，个人实名，开发方式「独立开发」、权利取得「原始取得」、权利范围「全部权利」，软件全称 `河医大助手校园教务辅助软件`、版本号 `V1.1.17`，与 PDF 页眉一字不差。费用 0 元（2017 年起取消登记费），材料齐全后 30–60 工作日出证。材料已备齐，你本人只需身份证正反面 + 在线填表打印手写签字。[登记办法（WIPO 收录）](https://www.wipo.int/wipolex/en/text/199387) · [办理流程](https://www.ssia.org.cn/page52?article_id=52) · [2025 材料规格：源程序前后各 30 页、每页 ≥50 行](https://blog.csdn.net/m0_75269526/article/details/148378686)
2. **补统一版权头**：`Copyright (c) 2026 孤汩. All rights reserved.` + 「本程序以 AGPL-3.0 授权」，覆盖 `web/*.js`、`core/*.py`、`server/worker.js`、`android/src/**/*.java`、`tools/*.py`；关于页加一行版权与许可证。
3. **签名证书离线备份两份**（U 盘 + 私人邮箱附件），口令另存。丢了以后发的包就少了「同一个开发者」这条链。
4. **归档权属证据包**：`git bundle` 全历史快照 + `git log` 导出 + Release 页打印 + 官网存档截图 + 两份软著 PDF，打包并逐个记 SHA-256。
5. **AGPL-3.0 与公开仓库保持原样**。

覆盖范围：抄代码后闭源商用、抄代码后做成网络服务却闭源（AGPL 第 13 条专门堵这个，[ reciprocity 研究](https://doaj.org/article/93eaa284050c4f6dbfeaa2c9a9432a9b)）、冒名发布 APK（签名指纹一比即穿）、平台投诉/应用市场申诉缺官方凭证。[SANER 2019 实测 1000 个二进制项目 7.2% 存在 GPL/AGPL 违规，说明同源可检测、可维权](https://doi.org/10.1109/saner.2019.8667977)

覆盖边界：依法 fork、自行修改、自行部署、给同学用（AGPL 明示允许，条件是同样开源并保留署名）；功能构思的独立重写。

成本：0 元 + 你本人约 1 小时填表；我这边约半天落码归档。线上影响：**0**（APK、cfg.latest、官网、GitHub 全部保持）。

### B 收紧型 = A 全部 + 名字注册 + 源码转私有

在 A 之上加：

6. **注册「河医大助手」文字商标**，主类第 9 类「可下载的计算机程序」，第 42 类「计算机软件设计 / SaaS」、第 35 类一并考虑，先做近似检索再提交。参考（2022）沪 0115 民初 29055 号：App 名称一字之差的近似标识被认定构成商标性使用并判侵权，第 9 类最关键；同案也确认「在先使用 + 有一定影响」是对方的抗辩口，越早申请越干净。
7. **GitHub 转私有**，或拆成「公开壳（README + 截图 + Releases）+ 私有源码仓」。`publish/GITHUB-发布指引.md:163-171` 已写好这套形态。
8. 公开过的副本继续存在（已被 clone / 缓存的历史收不回），因此 A 的软著与时间戳仍是主凭证，私有化只减少**后续新增**曝光。

覆盖范围：名字被蹭、被抢注后反咬、新版实现持续被围观照抄。

取舍：失去公开 commit 时间戳这条最直观的证据，第三方也失去「验证你真写了这些代码」的途径；社区信任与协作下降。AGPL 对已公开副本继续有效，新代码改专有许可需单独声明。

成本：商标官费 + 数月审查；仓库一次迁移。线上影响：官网/APK 保持，GitHub 可见范围变化（需你点头才动）。

### C 运营型 = A 全部 + 把「抢市场」变成跑得快

在 A 之上加：

9. **官方入口唯一化**：官网、QQ 频道正文、GitHub Release、关于页四处统一作者署名与「唯一官方入口」，短链/镜像一目了然。
10. **首发与更新节奏留痕**：每版本 Release + notes + 双入口验收 + QA 报告（现有链路已是这套，继续跑），形成连续公开使用证据。
11. **关于页加「验包」入口**：把 `/v1/config` 的版本号 + 签名证书指纹摆出来，用户自己就能核对拿到的包是不是你发的。
12. **抄袭处置脚本化**：代码同源比对（特有标识、文件名、注释、字符串常量）→ 平台 DMCA / 应用市场投诉 → 律师函 → 诉讼。参考（2025）黔民终 27 号，法院认的就是「源代码署名 + 软著登记证书 + 实质性相似」三件套；[（2015）浙甬知初字第 71 号](https://wenshu.court.gov.cn/website/wenshu/181107ANFZ0BXSK4/index.html?docId=de3d6dc6040e474ba97bba58bc556195) 也以软件上署名与登记证书认定权属。

覆盖范围：山寨包冒充官方、用户被导流到仿冒入口、纠纷时缺现成取证材料。

取舍：靠持续运营，属于日常纪律而非一次性动作。成本：低，复用现有发布链。线上影响：关于页与官网一处小改动（需你点头）。

## 3 推荐

**先走 A，商标（B 的第 6 项）并行启动，C 作为日常发布纪律沿用，仓库转私有先缓。**

理由：

- A 是唯一把「属于我」变成**官方凭证**的一步，且完全保持你已经上线的东西。
- 商标审查周期最长，是唯一覆盖「名字被蹭」的工具，越早排越好。
- 公开时间戳目前对你更有利，转私有等你说要再动。

## 5 一句实话

证书保的是「这行代码是你写的」「这个名字是你的」；市场靠官网、更新速度、口碑和唯一官方入口守住。把权属坐实之后，别人就算另写一套，也得自己从头写，并且承担「闭源即违反 AGPL」的后果。
