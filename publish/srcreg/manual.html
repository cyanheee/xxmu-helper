一、软件概述

1.1 软件用途

本软件是面向河南医药大学在校学生开发的教务辅助工具。学校现有教务系统与在线学习平台分散在两处，课表、作业截止时间、考试安排需要分别登录查看，每次都要重复输入账号、翻找入口。本软件把这两处信息汇总到同一界面，并把「本周上什么课、哪份作业快到期、哪间教室空着」这几件每天都会问的问题做成一眼可见的页面。

1.2 开发背景

开发者为该校在读学生，日常需要频繁查看课表与作业。现有官方入口虽然可用，但存在三个具体不便：一是每次都要重新登录，会话容易失效；二是作业分散在多门课程下，临近截止时容易漏看；三是查询空闲教室需要手动比对课表。本软件针对这三点做了针对性设计。

1.3 软件特点

  • 本地优先：课表与作业数据全部保存在设备本地，用户密码不经过任何服务器。
  • 失败可见：任何数据读取或解析失败，都以可读中文提示呈现，不使用静默默认值，避免把「读不出来」显示成「没有数据」。
  • 零构建依赖：界面为纯静态资源，不依赖前端框架与打包工具，体积小、启动快、便于长期维护。
  • 离线可用：无网络时仍可查看已缓存的课表与作业。

四、功能说明

4.1 课表

登录教务系统后，软件读取本学期的课表页面并解析为结构化数据，按周渲染成七列网格（周一至周日 × 节次）。当前周整列高亮，今天所在列顶部加标记。每门课显示课程名称、教室、起止时间。

页面顶部设有一条状态说明栏，用于区分四种不同情况：尚未同步、本周确实没有课、课表已同步但周次信息无法识别、数据读取失败。这四种情况在视觉上必须可区分 —— 否则用户看到的都是「一张空白表格」，无法判断是自己没同步还是软件出了问题。

功能操作说明
切换周次点击顶部周次行左右箭头可在本学期全部周次间切换
查看课程详情点击课程块弹出浮层显示完整名称、教师、教室、周次
同步课表点击「同步」按钮重新登录教务并读取
复制诊断信息点击状态栏上的「复制课表诊断」复制学号、周次覆盖范围、本周课程数、无法识别的周次原文
查看原文「我的 → 诊断 → 查看课表抓取原文」保留教务返回的页面片段，供排查解析问题

4.2 学习（作业与考试）

从在线学习平台读取各门课程的作业与考试，统一转换为同一数据结构后排序展示。默认按紧急程度排序，也可切换为按课程分组。

状态字段的处理是这一模块的关键：平台返回的状态文案存在多种写法，软件对可识别的状态归类为「待做 / 待批阅 / 已完成 / 已过期」，并对**无法识别的状态一律标记为「未知」而不是「已完成」**。设计理由：把未知判成「已完成」会让用户错过截止时间且不可恢复，判成「待做」最多让用户多点开看一次，代价可逆。

功能操作说明
切换排序顶部「按紧急度 / 按课程」选择结果保存在本地
筛选类型顶部「全部 / 作业 / 考试」选择结果保存在本地
打开作业点击卡片在软件内置浏览器打开平台页面（保留登录态）
查看倒计时卡片右侧每分钟刷新，不重建列表，保持滚动位置

4.3 空教室

基于用户本人课表中出现过的教室集合，计算指定周次、星期与节次下的空闲教室。计算分两种口径：指定单日时空闲指「当天该时段没课」；不指定日期时空闲指「整周该时段都没课」，适合找固定自习位置。

局限性说明：软件只能看到用户本人课表中出现过的教室（通常十几间），无法得知其他班级的课程安排，因此结果仅供参考；需要精确结果时，界面提供跳转教务系统空闲教室查询的入口。

4.4 校园事务

提供饮水机的远程解锁与定量停止功能。用户在机器上扫描一次二维码后，机器信息保存在本地，之后可直接在手机上操作。

该功能的能力边界需明确说明：第三方平台仅提供「解锁」接口，解锁后仍需在机器出水口按一下物理按键才会出水，平台未开放远程开阀能力；但「停止」可以远程下发，因此软件提供「设定目标水量、到量自动停止」的功能。

功能操作说明
绑定设备扫码或手输机器码读取机器名称、编号与出水口列表
放水点击「放水」下发解锁命令并等待机器回执
停止点击「停止」下发停止命令，轮询至机器确认停止
定量放水先选目标水量再放水轮询累计用水量，达到目标后自动停止
重新绑定点击「重新绑定」重新读取机器信息与出水口编号

4.5 校园资料与留言

内置学校常用信息条目，包括教务与学习平台入口、办事流程、常用联系方式等，支持关键词检索与本地新增条目。

另设有留言板，学生可提交意见与问题；提交内容经管理员审核后公开展示。为避免信息泄露，公开留言的署名统一显示为「同学」，不包含学号信息。

4.6 我的

集中管理账号与偏好：查看当前学号、已绑定设备、软件版本，提供检查更新、查看使用教程与使用声明、退出登录等入口。管理员账号额外显示管理控制台入口，可查看使用名单、发布公告、上传新版本。

4.7 版本更新

软件启动后异步检查服务端配置，发现新版本时弹出提示。更新策略分三档：不提示、每次启动提示、强制更新（低于最低版本时拦截）。为避免误拦截，强制更新设有前置校验：若未配置下载地址则不允许开启，防止把用户挡在门外却无路可退。

5.3 数据同步机制

课表与作业数据按以下优先级读取，任一层取到有效数据即停止：

  • 第一层：设备外部目录中的 JSON 文件（可由电脑端脚本推送）
  • 第二层：软件私有目录中的缓存文件（上次同步结果）
  • 第三层：安装包内置的默认数据

每一层都会区分「没有数据」与「读取出错」两种结果。读取出错时不会静默降级到下一层，而是记录错误原因并提示用户，避免把「读取失败」显示成「你还没同步」。

七、技术特点

7.1 异步接口桥接

WebView 调用原生方法时，若原生方法内部执行网络请求，界面线程会同步等待返回值，网络缓慢时导致整个页面无法响应。本软件所有涉及网络的原生方法均采用「立即返回标识、后台执行、完成时回调界面」的异步模式，从根本上避免界面阻塞。

7.2 字符集自动识别

教务系统的页面编码为 GBK，而部分提示信息为 UTF-8。软件对响应内容先按 UTF-8 严格解码，失败则回退 GBK，从而在同一个软件中正确显示两种编码的页面，避免中文乱码。

7.3 失败可见原则

软件对三类容易「静默失败」的场景做了专门处理：

  • 数据读取失败：区分「文件不存在」与「文件存在但读不出」，后者记录原因并提示。
  • 解析失败：结构不完整的记录计数并提示「有 N 条未能识别」，不整体丢弃。
  • 网络失败：返回具体错误类型（超时 / 解析失败 / 服务端错误），不使用统一文案。

7.4 双入口与自动回退

服务端提供两个访问入口。软件在请求失败且失败原因为网络层错误时，自动切换到备用入口重试，并在成功后退一直使用可用入口。服务端返回业务错误时不切换入口 —— 因为那说明入口本身可用，切换只会造成重复请求与额外等待。

7.5 安全设计

  • 用户密码不经过开发者服务器，登录在软件内置浏览器中直接提交给学校官方页面。
  • 服务端仅保存版本配置、公告与设备数量等轻量状态，不保存课表与作业内容。
  • 设备识别使用本地生成的随机串哈希，不采集硬件标识。
  • 管理接口使用独立口令校验，采用定长比较避免时序侧信道。
  • 明文 HTTP 流量默认拒绝，仅对学校与必要平台域名开放白名单。

现象可能原因处理方式

9.1 崩溃日志

软件在启动最早阶段安装全局异常捕获，将异常堆栈、设备型号、系统版本与 WebView 版本写入软件私有目录，并在界面上提供「复制诊断信息」入口，便于在无法连接调试设备时定位问题。

十、其他说明

10.1 软件性质

本软件为开发者个人独立开发的辅助工具，与学校及任何第三方平台不存在隶属或合作关系。软件中的课表、作业等信息均来自学校官方系统，一切正式事务（成绩、选课、评教、缴费等）以学校官方系统为准。

10.2 数据归属

软件展示的所有教务与学习数据均属于用户本人，由用户通过自己的账号登录后获取，仅存储于用户设备本地。开发者不收集、不存储、不转售任何学生的个人信息。

10.3 版本维护

软件按需迭代，每次发布均保留安装包与对应版本的源代码快照，以便回溯与验证。当前说明对应版本 V1.1.17。

十一、各界面详细说明

11.1 启动与使用声明界面

首次启动时先展示「使用声明」，内容包括：软件性质（学生自建、非官方）、数据来源（学校官方系统）、密码处理方式（不经过开发者服务器）、以及「以官方系统为准」的免责说明。用户确认后进入学号填写界面。

设计取舍：声明放在教程之前而不是之后。用户第一次打开软件时注意力最集中，此时告知性质最有效；若放在教程之后，用户已经连点过若干页「下一步」，到最后一页只会继续连点，声明形同虚设。

11.2 主界面与导航

主界面由三部分组成：顶部品牌区、中部内容区、底部导航栏。品牌区显示软件标识与当前页面名称；底部导航固定显示五个一级入口。

导航层级设计

底部导航只表示一级页面。「关于」「使用帮助」「管理控制台」等属于二级页面，从「我的」进入，进入后底部导航的高亮仍停留在「我的」，顶部显示返回箭头与面包屑。这样用户始终知道自己处在哪一层，返回键的行为也有确定含义：先关浮层，再回上级页面，最后才退出。

十二、关键处理逻辑

12.1 课表页面解析

教务系统返回的课表是二维表格，每个单元格的编号由「星期」与「节次」拼接而成，单元格内部包含课程名称、教师、教室与周次信息。解析步骤如下：

① 按单元格编号定位
   编号格式：k + 星期(1位) + 节次(1~2位)
   例：k11 = 周一第1节，k110 = 周一第10节
   ↓
② 提取单元格内的课程文本块
   匹配包含「padding-bottom」与「clear」两个样式属性的块
   两个属性用独立前瞻断言，不考虑出现顺序
   ↓
③ 按分隔符切出 课程名 / 教师 / 周次 / 教室
   ↓
④ 把周次字符串转换为数组
   「1-16周」「1,3,5-9」「2-4[1-2]」等写法统一展开为整数数组
   ↓
⑤ 合并同一课程在连续节次的多个单元格为一个课程块
   合并键 = 课程名 + 教室
   ↓
⑥ 处理节次冲突
   两门课占用同一时段时不丢弃任何一门，按各自起始节次叠放
   并在状态栏提示存在冲突

第 ① 步的编号位数需要特别注意：若只按一位节次匹配，第 10 节及以后的课程会整块失配并静默消失，不报错也不提示。这对晚上排课较多的专业影响尤为明显。当前实现按 1~2 位节次匹配。

第 ② 步的属性顺序同样需要注意：若用串联通配符匹配，只在「padding-bottom 在 clear 之前」时成立；一旦页面把两个属性的顺序调换，整块课程就会失配。当前实现使用并列的前瞻断言，与顺序无关。

12.2 作业状态归一化

在线学习平台返回的作业状态文案存在多种写法，且不同课程可能不同。归一化过程分三级：

原始文案（如「待做」「未交」「进行中」「已完成」「待批阅」…）
   ↓ 一级：精确匹配已知状态表
   ↓ 二级：关键词匹配（含「完成」→ 已完成；含「未」「待」→ 待做）
   ↓ 三级：均不匹配 → 归为「未知」
   ↓
分组：待做 / 待批阅 / 已完成 / 已过期 / 未知

默认值方向经过专门权衡：平台新增状态文案时，若默认判为「已完成」，用户会错过截止且无法挽回；若默认判为「未知」并单独成组，用户最多多点开看一次。因此三级匹配失败一律归入「未知」，并在界面明确标注。

12.3 空教室计算

输入：用户本人课表中的课程集合、目标周次、目标节次区间、目标星期。

全部教室 = 课表中出现过的教室去重集合
占用教室 = 满足以下全部条件的课程所在教室：
            周次包含目标周次
          ∧ 节次区间与目标区间有交集
          ∧ 星期等于目标星期（若指定）
空闲教室 = 全部教室 − 占用教室

目标星期参数是必需的：若省略该条件，询问「周三下午」时会把「周一上午有课」的教室也算作占用，得出错误结论。不指定日期时采用整周保守口径——任一天该时段有课即视为占用，适合寻找固定自习位置。

12.4 缓存读取的三层优先级

数据读取按以下顺序，任一层取到有效数据即返回：

① 外部目录 JSON 文件
     不存在  → 下一层
     存在但读取失败 → 记录错误，仍然下一层（但不静默）
     存在且有效 → 返回
   ↓
② 私有目录缓存文件（同上三态判断）
   ↓
③ 安装包内置默认数据

关键在于「不存在」与「读取失败」必须区分：若两者都返回空值，读取失败会被上层理解为「没有数据」，进而降级到第三层的内置数据，导致用户看到旧数据却显示为「已同步」。
