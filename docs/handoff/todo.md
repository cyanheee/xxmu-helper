## 四、已经查清、不用再怀疑

> 这一节**不是待办**。每条都是踩过一次、已经落地了防线的问题，
> 写在这里是为了下一次加功能时能直接对照，而不是重新推一遍。

- [x] **真机连接方式**（每次都要重来）：`adb pair HOST:PAIR_PORT 配对码` →
      `adb connect HOST:CONNECT_PORT`。无线调试的连接端口**每次重连都变**
      （配对端口与连接端口无关，配对成功后不用再配对）；找不到端口时扫 30000-65535。
      `adb devices -l` 空 + `adb mdns services` 空 = 手机没开无线调试，只能请用户开。
- [x] **PATH 里的 `adb` 是坏的**。`C:\Windows\system32\adb.exe` 是 1.0.32 老版本。
      真正的 adb 在 `D:\android-sdk\platform-tools\adb.exe`（1.0.41 / 37.0.1），
      命令里写全路径。这个坑会让「手机没连上」和「adb 本身坏了」看起来一模一样。
- [x] **改中文文件只能用 read/edit/write 工具**。v1.1.2 那次用
      `Get-Content -Raw` + `-replace` + `WriteAllText` 把 `index.html` 写坏：
      字节数 37434 → 42457、行数 722（应 763）、`<title>` 变成 `娌冲尰澶у姪鎵?/title>`。
      **`[Text.Encoding]::UTF8.GetString` 是宽容解码，不产生 U+FFFD，
      所以「replacementChars=0」证明不了没坏** —— 靠字节数对比与 `check_web.js` 的乱码指纹。
- [x] **解析类 bug 的失败方式是静默**。v1.1.5 两个 bug（占位符当学号、状态读不到当已完成）
      都是「不报错、不警告，只默默给错答案」。这类改动必须配三样：
      ①离线断言；②静态锚点（防「顺手简化」改回去）；③**原始输入留样**
      （`CX.diag()` + 「查看作业状态原文」按钮）。缺第③条时，下次改版只能重新猜。
- [x] **拿不准时的默认值要考虑「错了有多贵」**。作业状态判成「待做」最多多点开看一眼，
      判成「已完成」会让他错过截止、不可逆 —— 所以 `unknown` 一律站「还得做」。
      同理 `test_hwstatus.js` 里「未交 + 已过截止」我第一版期望写反了，
      跑出 FAIL 才纠正：**测试期望本身也会朝「看起来更整洁」的方向漂**。
- [x] **Worker / Pages Functions 里写 `cache-control` 不会让边缘缓存**。
      Worker 响应默认不进边缘缓存，必须显式 `caches.default.put()`。
      改成 `edgeCache()` 包装器 + `x-edge: hit|miss` 响应头 ——
      **有这个头，缓存生效没生效连打两次就能验**。
- [x] **管理接口要同时防「放大」和「写额度」**。KV 免费额度 10 万读 + **1 千写**/天，
      用 KV 做限流计数器等于把防刷本身变成刷。限流一律用 isolate 内存 `Map`；
      另加体积上限（`content-length` 早退）与条数硬上限（待审 ≥40 张直接拒），
      这两条不依赖内存状态、跨 isolate 有效。
- [x] **免费额度的天花板要按「单个请求的子请求数」算**。免费版单请求最多 50 次子请求，
      `handleAdminFeedback` 原来一次读 200 条留言正文 —— 超过 51 条这个接口就永远 500，
      还报「服务端忙」。**列表接口必须分页，且页大小留余量**（现 `PAGE = 40`）。
- [x] **写额度比读额度稀缺得多**，要看住「每次请求写几次」。`/v1/activate` 原来 3 读 3 写，
      其中「激活时把整个名单索引重写一遍」最致命。修法不是加限流，而是**别写**：
      `idxApply` 只在真有变化时才 `putIdx`。凡是「每次都写」的记账逻辑，
      都要问一句「这次真的变了吗」。
- [x] **锁在 UI 线程的图片解码不一定会 ANR，但一定会被系统杀掉**。
