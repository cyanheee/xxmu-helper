## 四、已经查清、不用再怀疑

> 这一节**不是待办**。每条都是踩过一次、已经落地了防线的问题，
> 写在这里是为了下一次加功能时能直接对照，而不是重新推一遍。

- [x] **真机连接方式**（每次都要重来）：`adb pair HOST:PAIR_PORT 配对码` →
      `adb connect HOST:CONNECT_PORT`。无线调试的连接端口**每次重连都变**
      （配对端口与连接端口无关，配对成功后不用再配对）；找不到端口时扫 30000-65535。
      `adb devices -l` 空 + `adb mdns services` 空 = 手机没开无线调试，只能请用户开。
- [x] **PATH 里的 `adb` 是坏的**。`C:\Windows\system32\adb.exe` 是 1.0.32 老版本。
      真正的 adb 在 `D:\android-sdk\platform-tools\adb.exe`（1.0.41 / 37.0.1），
      命令里写全路径。这个坑会让「手机没连上」和「adb 本身坏了」看起来一模一样。
- [x] **改中文文件只能用 read/edit/write 工具**。v1.1.2 那次用
      `Get-Content -Raw` + `-replace` + `WriteAllText` 把 `index.html` 写坏：
      字节数 37434 → 42457、行数 722（应 763）、`<title>` 变成 `娌冲尰澶у姪鎵?/title>`。
      **`[Text.Encoding]::UTF8.GetString` 是宽容解码，不产生 U+FFFD，
      所以「replacementChars=0」证明不了没坏** —— 靠字节数对比与 `check_web.js` 的乱码指纹。
- [x] **解析类 bug 的失败方式是静默**。v1.1.5 两个 bug（占位符当学号、状态读不到当已完成）
      都是「不报错、不警告，只默默给错答案」。这类改动必须配三样：
      ①离线断言；②静态锚点（防「顺手简化」改回去）；③**原始输入留样**
      （`CX.diag()` + 「查看作业状态原文」按钮）。缺第③条时，下次改版只能重新猜。
- [x] **拿不准时的默认值要考虑「错了有多贵」**。作业状态判成「待做」最多多点开看一眼，
      判成「已完成」会让他错过截止、不可逆 —— 所以 `unknown` 一律站「还得做」。
      同理 `test_hwstatus.js` 里「未交 + 已过截止」我第一版期望写反了，
      跑出 FAIL 才纠正：**测试期望本身也会朝「看起来更整洁」的方向漂**。
- [x] **Worker / Pages Functions 里写 `cache-control` 不会让边缘缓存**。
      Worker 响应默认不进边缘缓存，必须显式 `caches.default.put()`。
      改成 `edgeCache()` 包装器 + `x-edge: hit|miss` 响应头 ——
      **有这个头，缓存生效没生效连打两次就能验**。
- [x] **管理接口要同时防「放大」和「写额度」**。KV 免费额度 10 万读 + **1 千写**/天，
      用 KV 做限流计数器等于把防刷本身变成刷。限流一律用 isolate 内存 `Map`；
      另加体积上限（`content-length` 早退）与条数硬上限（待审 ≥40 张直接拒），
      这两条不依赖内存状态、跨 isolate 有效。
- [x] **免费额度的天花板要按「单个请求的子请求数」算**。免费版单请求最多 50 次子请求，
      `handleAdminFeedback` 原来一次读 200 条留言正文 —— 超过 51 条这个接口就永远 500，
      还报「服务端忙」。**列表接口必须分页，且页大小留余量**（现 `PAGE = 40`）。
- [x] **写额度比读额度稀缺得多**，要看住「每次请求写几次」。`/v1/activate` 原来 3 读 3 写，
      其中「激活时把整个名单索引重写一遍」最致命。修法不是加限流，而是**别写**：
      `idxApply` 只在真有变化时才 `putIdx`。凡是「每次都写」的记账逻辑，
      都要问一句「这次真的变了吗」。
- [x] **锁在 UI 线程的图片解码不一定会 ANR，但一定会被系统杀掉**。
      正确姿势是两段式：先 `inJustDecodeBounds` 读尺寸，`while (longest/sample > N) sample *= 2`
      粗采样，再按 `inSampleSize` 精确解码。**采样比缩放省在解码前。**
- [x] **下载完不校验哈希 = 把「装坏包」当成正常分支**。分段并发只保证每段长度对。
      校验要流式（`DigestInputStream`），不能用 `readAllBytes`；
      第二参设计成空串可跳过（老前端不传时不至于直接失败）。
- [x] **「读失败」和「没数据」在界面上长得一模一样，是本项目最反复的坑**（v1.1.9 又修一次，
      v1.1.22 的 mytodo 从一开始就按这条设计）。规律：凡是 `catch → return 空值` 的读路径，
      都要额外带出一句人话的原因（模块级 `LAST_READ_ERR` + `readErr()` 导出）。
- [x] **`catch` 里返回默认值 + 缓存 = 把「一次故障」固化成一分钟的「新常态」**。
      `getCfg` 原来读空和 JSON 损坏都回落 `DEFAULT_CFG` 并缓存 60 秒。
      修法不是加日志，而是**改默认动作**：读不出来就不缓存，下次重试。
- [x] **无凭证接口的写放大要设硬上限，但上限的落点要选在「损害最小处」**。
      `IDX_CAP = 5000` 时特意让**激活本身继续成功**（票照发、课表照看），
      只把「入名单」停掉 —— 损害从「全校当天不能用」降到「名单少几条」。
- [x] **Pages Functions 里把 `await request.arrayBuffer()` 裸露在 try 外，
      会把平台默认 500 HTML 弹给用户**。客户端按 `|` 拆不开，整段 HTML 显示在手机上。
      修法：包 try 并回 413 + JSON。**所有跨进程边界的异常都要自己兜成契约格式。**
- [x] **KV 的 REST 读接口返回原始字节，不是数字数组 JSON**。早期脚本多套一层 `JSON.parse`，
      把 `idx` 读成 `"       "`（一堆空格），看起来像「索引是空的」。
      判据：响应头 `content-type: application/octet-stream`，`buf.toString('utf8')` 直接可用。
- [x] **新加一层「必须看见」的弹窗，要按 z-index 全场排序来定**（v1.1.11）。
      `#disc` 最初写 74（「比 `#tut` 的 70 高一层」），但 `#gate` 100 / `#upd` 120 /
      `#ntc` 125 / `#onb` 130 —— 被盖住 = 没看见，而且用户以为「点不动」。
      **定 z-index 之前先把全表拉出来排一遍**，只跟相邻的比较一定漏。
- [x] **同一个开关变量别在两层都清**。`disc.js` 里 `show()` 清 `replayMode = false`，
      而 `replay()` 是「先置 true 再调 `show()`」→ 立刻被自己踩掉。
      **一个标志只该有一个写入点**；两个入口都需要它归零，那是两个函数。
- [x] **`wrangler secret put` 从 PowerShell 管道读会带尾随换行**（v1.1.12）。
      wrangler 打印 Success，但 `constEq` 逐字节比对永远不等，所有管理请求 401。
      **任何「逐字节比对」的凭据，写入前先落一个无 BOM 无换行的文件，
      再 `cmd /c "type 文件 | wrangler secret put KEY"`；写完必须用真实请求验一次。**
- [x] **属性被当成函数调用 = 整个入口从第一行就断了，界面上一个字都不会说**（v1.1.12）。
      `AUTH.Admin.key` 是字符串属性，写成 `AUTH.Admin.key()` → 必然抛 TypeError。
      **①一个值有几种形态，调用点必须唯一；②一个动作的失败提示要写在同一处可见位置；
      ③静态锚点要剥注释再查 —— 修复说明的注释里就引用了那个错误写法。**
- [x] **「界面什么都不说」有时不是没写提示，而是提示被排版挤出了屏幕**（v1.1.13）。
      `#kbtip` 一直都有，但写在 `#grid` 后面，网格本身就 690px，手机一屏装不下 →
      「没同步」「周次没读懂」「本周没课」三种状态在屏幕上完全一样：一张白纸。
      **状态类信息一律排在会被滚动的长内容之前**，并给位置关系写硬断言
      （`indexOf('id="kbBar"') < indexOf('id="grid"')`）。
- [x] **正则「写宽松」不等于「写对了」**：串联的 `[^>]*` 只放宽了空格和引号，没放宽顺序。
      正解是两个独立前瞻 `(?=[^>]*A)(?=[^>]*B)`。
      **凡是要「顺序无关」就用并列前瞻，并且必须造一个「换序样本」的测试用例。**
- [x] **解析器丢数据的方式是「整格消失」，不是抛异常**（v1.1.13）。
      `cellRe` 里 `id=['"]k(\d)(\d)['"]` 只认一位节次，第 10 节 `k110` 会失配，
      那一格连同里面的课一起消失，不进 `bad[]`、不报错。
      **编号位数必须显式给上界（`\d{1,2}`），回归用例必须有两位数编号的样本。**
- [x] **「点了没反应」的第二种形态：内容真的生成了，只是落在视口外面**（v1.1.14）。
      `display:none → block` 不等于「用户看见了」，凡是展开一块内容，
      必须同时决定「它在哪、要不要滚过去」。
- [x] **`publish_apk.py` 原来没有网络重试**，一次 TLS 握手抖动就整趟发布中断（v1.1.14）。
      **①所有发往境外的写操作都要带退避重试；②只重试网络层异常，
      `urllib.error.HTTPError`（4xx/5xx）是明确答复，重试只会把「口令错」变成「等 12 秒后还是错」；
      ③重试日志要打出来。**

- [x] **重复出包 SHA 会变，但字节数相同**（v1.1.22 实测）：同一份源码在新位置重出，
      仍是 571000 字节、同样的 `aapt2 dump badging` 版本号，但 SHA-256 从
      `33E4D744` 变成 `2BD6E29C`。原因是 zip 时间戳与签名块带时间。
      **所以「SHA 不同」不能直接判成「内容不同」**，要判内容得比 assets 逐字节 + badging。
      两份都留在 `旧版本\`（`河医大助手-v1.1.22-迁移前构建.apk`）做留证。
- [x] **`--no-publish` 会留下「blob 新、cfg 旧」的坏包状态**（v1.1.22，我自己踩的）。
      它不切 `cfg.latest`，但确实换了 `apk:blob`，而客户端下载后要拿
      `cfg.latest.sha256` 校验 → 学生点下载拿到新字节、校验失败、装不上且无提示。
      现在脚本自动把 blob 恢复成 `cfg.latest` 声明的那一份（按 sha256 找回，不按文件名）。
      **判据：任何「存了但没发布」的操作，都不能让「下载到的东西」和「声明的 hash」不一致。**
- [x] **一个永远红的检查，等于没有检查**（v1.1.35 才发现，已红了十个版本）。
      `tools/verify_apk.py` 的「四件套」从 v1.1.23 起一直 `[FAIL]`：
      它还在断言 v1.1.14 那套内嵌详情卡（`showDetail(id, fromRow)`、`DETAIL_FROM`、
      `admDetailCard`、`admDetailBody`），而这些在 v1.1.23 已经整体换成全局半框 `#sheet`。
      **删功能时忘了删它的锚点** → 从 v1.1.23 到 v1.1.34，没人再跑过 verify_apk，
      它本该拦住的那类问题（dex 里少类、assets 没同步、worker 没部署）这段时间全靠运气。
      **规则：①改/删一个功能，同一个提交里改它的锚点；②任何检查一旦红了，
      要么当场修好，要么当场删掉——不许「先放着，等会儿看」。**
- [x] **「静态体检全 PASS」可能只证明了一半的链路**（v1.1.35，本项目最贵的一次）。
      课程提醒从 v1.1.27 做到 v1.1.34，`check_web.js` 一直 PASS、包一直能出、
      前端 `reminder.js` 写得完整 —— 但真机上**一次都没响过**。三处断点全在
      Android 侧，而所有断言都只写在前端侧：
      ①`AndroidManifest.xml` 没有 `<receiver>`，`AlarmManager` 挂上的
        `PendingIntent` 指向的 BroadcastReceiver 没注册 → 广播无人接收；
      ②没有声明 `POST_NOTIFICATIONS`，Android 13+ 上 `requestPermissions`
        因为「权限没声明」当场被拒，`canNotify()` 恒 false；
      ③没有 `RECEIVE_BOOT_COMPLETED` + 开机重挂，重启后闹钟静默清空，
        而界面上仍显示「已开启」。
      **判据要落在「这条链路的每一端都在吗」，而不是「我写的那一端写对了吗」。**
      现在 `check_web.js` 的 v1.1.35 段同时断言 manifest 的 receiver 与权限，
      `tools/test_reminder.js` 做三段（前端计算 / Java+manifest 接线 / 前后端契约）。
      **另一条更要紧的**：`reminder.js` 顶部那句「无法离线验证，只能真机确认」，
      写下来之后**必须真的去真机确认，否则它只是一句免责声明**。
- [x] **APK 总字节数相同，不能推出「改动没打进去」**（v1.1.35）。
      v1.1.32 / 1.1.33 / 1.1.34 / 1.1.35 四个包全是 591665 字节，
      但 zip 条目逐条比：`AndroidManifest.xml` 1425→1731、
      `assets/reminder.js` 3317→4305、`classes.dex` 306335→307688 ——
      增量被签名块与对齐填充吸收了。

      （`ReminderScheduler` / `BootReceiver` 在 1.1.34 为 False、1.1.35 为 True），
      不要看文件大小，也不要只看 `badging` 的版本号。
- [x] **`reset --hard origin/main` 在 `fetch` 失败时是灾难**（v1.1.22）。
      github.com 连不上时 fetch 会失败、`refs/remotes/origin/main` 仍是旧 sha，
      于是 reset 把刚推上去的提交连同未提交改动一起退回上一个提交 ——
      内容已经在远程了，本地反而丢一份。`push_via_api.py` 现在自己对齐引用、
      用 API tree 逐文件比 blob sha 证明「内容一致」，并只提示 `--soft`。
- [x] **完美校园的查询接口没有「只读按房间号查」的口子**（v1.1.36 实测）。

      `-20005 命令字不存在`（它只在加密的 `SWAEEncryptServlet` 通道里有）。
      **所以「不绑定也能查」这条路根本不存在**，只能把「每次重选」压成「只选一次」。
      另外 `bindroom` 是**累加**不是替换（连绑两间 `existflag=2`），
      换房间必须先 `unbindroom` 旧的，否则服务端列表越攒越长。
- [x] **服务端会静默接受错参数名并返回全量数据**（v1.1.36）。
      `getfloorlist` 的参数必须是小写 `buildid`；写成 `buildId` / `buildingid` /
      `id` 都不报错，直接把全校 221 条楼层全返回。这类「不报错但答案全错」
      比报错难查得多 —— `test_elec.js` 因此专门断言「没有写错成 buildId/buildingid」。
- [x] **真机切后台时 WebView 可能仍报 `document.hidden === false`**（v1.1.36）。
      只挂 `visibilitychange` 收不到「回来了」这个信号，必须在 Java 侧
      `onResume` 里 `evaluateJavascript("window.__onResume && window.__onResume()")`
      补一条。用 `evaluateJavascript` 而不是 `loadUrl("javascript:…")` ——
      后者会把返回值当导航。
- [x] **缓存下来的数字必须能「认领」到当前对象**（v1.1.37）。
      入口卡上放上次查到的度数，看着是省一次点击，但那个数字属于**上次那间房**。
      换房间后如果还贴着，学生会拿旧房间的 57.72 当自己宿舍的余量去算电费 ——
      比显示 `--` 糟糕得多。所以 `paintEntry()` 里有一条硬判据
      `c.rv === cur.rv`，不成立一律显示 `--`，`commit()` 换房后立刻重画。
      **同理 `--` 与 `0` 必须分开**：`0` 是「真的没电了」，`--` 是「不知道」，
      把两种状态画成同一个符号，等于把「不知道」谎报成「没电了」。
- [x] **出包前后总字节数相同 ≠ 没打进去（第二次栽）**（v1.1.37）。
